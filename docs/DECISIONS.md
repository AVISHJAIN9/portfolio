# Architectural Decision Records (docs/DECISIONS.md)

| ID | Decision | Reason | Date |
|---|---|---|---|
| **ADR-001** | **Shared-Core Monorepo Topology (`portfolio/`)** | Managing 20 standalone repositories concurrently causes severe code duplication in low-level primitives (varint, CRC32, ring buffers, caches). A shared-core monorepo enables single-source implementation in `platform/` with standalone per-project exports via `tools/export-project`. | 2026-09-30 |
| **ADR-002** | **Rust for Core Performance Engines** | Rust provides zero-cost abstractions, deterministic memory management without GC pauses, native SIMD intrinsic support, and memory safety for low-level systems (Rollback, QUIC, HNSW, LSM, Cache). | 2026-09-30 |
| **ADR-003** | **TypeScript / Next.js 14 for Frontend Consoles** | Provides static page pre-rendering, modern developer ergonomic toolchains, seamless integration with Canvas, WebGL (Three.js), and real-time WebSocket / SSE clients. | 2026-09-30 |
| **ADR-004** | **Python for AI/ML Modeling & Training** | Scikit-Learn, NumPy, and lightweight ONNX pipelines allow rapid, CPU-trainable model development (<15 min) with clean offline verification. | 2026-09-30 |
| **ADR-005** | **Offline-First & Deterministic Fallback Principle (Rule R6)** | Every engine, test suite, and demo must run without API keys, GPU hardware, or cloud connectivity. AI/ML layers must operate in `MODEL_MODE=heuristic` if trained weights or LLM keys are absent. | 2026-09-30 |
| **ADR-006** | **Procedural 3D Frame Sequence Generator Fallback** | Where physical video assets (`.mp4`) are not provided, `tools/frames-gen` renders deterministic Three.js scenes into WebP frame sequences headlessly, ensuring complete visual fidelity without missing asset blockers. | 2026-09-30 |
| **ADR-007** | **Zero-Float Invariant for Deterministic Simulation** | Simulation and state reconciliation paths in physics and netcode use Q16.16 fixed-point arithmetic (`FixedI32`) to eliminate cross-architecture IEEE 754 floating-point divergence. | 2026-09-30 |
| **ADR-008** | **Strict Non-Authoritative ML Governance** | No AI/ML model operates on authoritative state mutation or packet routing paths. All adaptive outputs are clamped by deterministic guardrails $[min, max]$ with instant kill-switch fallbacks. | 2026-09-30 |
| **ADR-009** | **Vendor-on-Export Strategy (Rule R3 / D7)** | Each project can be exported as an independent GitHub repository where only the specific `pf-*` platform crates consumed by that project are vendored with pinned versions and attribution. | 2026-09-30 |
| **ADR-010** | **Dynamic Multi-Layout Workbook Normalization** | Workbooks across the 20 projects use different layout conventions (01-style Master Roadmap, 04-style Detailed Analysis, 05-style layered sheets). `tools/feature-ingest` dynamically detects column semantics and normalizes all 800 features into canonical JSONL files. | 2026-09-30 |
| **ADR-011** | **Variable-Length Connection ID & CRC32 Framing for Mini-QUIC** | Implemented RFC 9000 Initial / 1-RTT packet parsing with `QuicVarInt` and hardware-accelerated CRC32 integrity framing to guarantee zero heap allocations on the packet decode hot path. | 2026-09-30 |
| **ADR-012** | **RFC 9002 Loss Recovery and Congestion Window State Machine** | Implemented smoothed RTT calculation, RTT variance tracking, packet loss detection via 3-packet reordering threshold, and slow-start / congestion-avoidance window throttling in `mini-quic`. | 2026-09-30 |
| **ADR-013** | **ZoneMap Pruning and SelectionVector in Columnar Engine** | Used min/max chunk-level ZoneMaps to prune non-matching horizontal RowGroups before memory load, coupled with `SelectionVector` filtering to avoid copying row data during multi-stage predicate evaluation. | 2026-09-30 |
| **ADR-014** | **S3-FIFO Algorithm for Query Result Caching** | Integrated `pf-cache::S3FifoCache` into the columnar query engine to manage query result sets with small, main, and ghost queues, outperforming LRU under scan-heavy workloads. | 2026-09-30 |
| **ADR-015** | **Layered Graph Navigation with RoaringBitmap Filtering in HNSW** | Coupled multi-layer proximity graphs with `RoaringBitmap` bitsets to support adaptive filtered vector search (in-graph candidate evaluation vs post-filtering), achieving sub-40µs top-10 queries. | 2026-09-30 |
| **ADR-017** | **Derived Feature ID Scheme (`<slot>-<3-digit index>`)** | Master workbooks lack universal semantic ID columns (# is a row index, 05 lacks IDs). Standardized derived ID `<NN>-<zero-padded index>` (e.g. 05-001) plus name SHA1 hash to ensure strict traceability and row-reorder detection without semantic invention. | 2026-09-30 |
| **ADR-018** | **Autonomous Excel Status Deliverables (`*_STATUS.xlsx`)** | Built `tools/workbook_status.py` using openpyxl to generate read-only verification workbooks under `evidence/workbooks/`. Added Feature ID, Implemented (✓/✗), Verified (✓/✗), Status, and Evidence columns, plus an `Implementation Status` sheet with live `COUNTIFS` rollup formulas and Arial styling. | 2026-09-30 |
| **ADR-019** | **Strict Prohibition on Workbook Reconstruction / Padding (Violation Recorded)** | Violation Recorded: In a prior session, an openpyxl script synthesized placeholder rows ("QUIC Core Protocol Mechanism P0 #N", hardcoded hours 4210) and copied 04 from another folder. This has been purged and prohibited. Enforced strict immutable requirement: master workbooks in `inputs/specs/` are read-only user-provided files with exact verified SHA256 hashes (`04: 6699a333...`, `05: 69429364...`). Zero synthetic generation permitted. | 2026-10-01 |
| **ADR-021** | **Standard TLS 1.3 QUIC Handshake via `rustls::quic`** | Standardized on `rustls` with the `quic` feature (`rustls::quic::{ClientConnection, ServerConnection}`) and `rcgen` self-signed certificates for the TLS 1.3 cryptographic handshake. Kept `pf-crypto` for RFC 9001 packet protection, AEAD, header protection masks, and RFC 7748 X25519 key agreements. | 2026-10-01 |
| **ADR-022** | **Parquet Reader via `parquet` Crate** | Used standard `parquet` crate for reading Parquet file schemas, row groups, and dictionary/plain columns into internal `Chunk` vectors, tested differentially against DuckDB. | 2026-10-01 |
| **ADR-023** | **LSM-Tree Storage Engine Architecture (Slot 06)** | Built high-throughput LSM-Tree KV store using modular platform primitives (`pf-wal`, `pf-checksum`, `pf-collections` Bloom filters, `pf-cache` Block cache) with write-ahead logging, concurrent memtable, SSTable formats with block indexes, and active manifest recovery. | 2026-10-01 |
| **ADR-024** | **CI Evidence Commit Integrity & Trace Correction** | Standardized automated evidence collection on clean Git clones (`git clone . /tmp/pf-ci && cd /tmp/pf-ci && make ci`) saving full test traces to `evidence/ci_run_<HEAD_SHA>.txt` with per-test pass/fail/ignored parsing. Corrected historical artifact: the previous evidence file was named `evidence/ci_run_aa2b944d88.txt` (reusing the commit sha from session 5), indicating it was not a clean run of that specific commit. All CI runs going forward are executed against newly generated HEAD commits on isolated `/tmp` clones. | 2026-10-01 |
| **ADR-025** | **Strict Workbook Name Enforcement & Row Alignment (Violation Recorded)** | Violation Recorded: In Session 7, some test annotations mapped feature IDs to inferred titles rather than the exact feature title from the master workbook's `Detailed Analysis` sheet (e.g. `04-001` mapped to "Vectorized execution engine core" when the master workbook defines row 1 as "SQL editor & query workspace" P1, and real P0s start at `04-021` "SQL lexer/tokenizer"; `05-026` was mapped to "Smoothed RTT" when `05-026` is "Duplicate ACK handling" and Smoothed RTT is `05-034`; `06-016` was mapped to "WAL checksums" when `06-016` is "WAL segment rotation" and checksums is `06-017`). Enforced mandatory syntax `// FEAT: <id> "<exact workbook name>"` and mechanical validation in `evidence_gen.py` and `test_workbook_status.py` that fails the pipeline if any annotation diverges from the master workbook. | 2026-10-01 |
| **ADR-026** | **Session 8 Feature Names Quarantine and Universal Status Reset (Violation Recorded)** | Session 8 feature names were not sourced directly from the master workbooks (e.g. `05-015` was named "TLS 1.3 handshake integration" instead of verbatim "X25519 key agreement"; `05-016` was named "HKDF" instead of verbatim "ChaCha20-Poly1305 packet protection"; `05-131` was mapped to P2 "AI-assisted troubleshooting workflow"; `04-127` was "Plan validation and sanity checks" instead of verbatim "SQL injection defenses"; `04-133` was "Bit-packed integer codec" instead of verbatim "CI/CD pipeline"). All Verified claims are quarantined and reset to Specified in `_STATUS.xlsx` and `PORTFOLIO_STATE.md` pending rigorous, feature-by-feature semantic re-audit with verbatim workbook names. | 2026-10-01 |
